# Contributing

1. Read RULES.md, docs/ARCHITECTURE.md, and relevant ADRs.
2. Confirm scope and acceptance criteria.
3. Add tests, documentation, and operational notes.
4. Run `make verify` and report unavailable checks.
5. Request appropriate review.

Seek prior maintainer approval for dependencies, migrations, contracts, authn/authz, cryptography, tenant isolation, CI, and IaC. Never deploy or modify production resources as part of a contribution.
